## 1. 法務の結論

**以下の5原則を守れば、日本法上は賭博罪・風営法・資金決済法・景表法・改正依存症対策基本法のいずれにも該当しない構造になる。**

1. 購入なし
2. 換金・景品なし（ランキング賞品も含む）
3. 譲渡なし（送金機能なし。プライベート卓は 2026-10-08 にさつきが導入を決定。02-legal.md §5）
4. 収益化なし（広告・寄付・アフィリエイトなし）
5. 実在の賭博サイトへの誘導なし（リンク・名称・「本番で稼ぐ」等の表現なし）

あわせて、次の点も守る。

- **「Spin & Go」はPokerStars側の登録商標**（日本の第6115614号ほか）なので、公開するアプリ名には使えない。他社の名称（Spin & Gold、Expresso、Twister、BLAST、SPINS、Spinz）も避ける。
- 海外のリスク（米ワシントン州、韓国、中国、豪州、GDPR）は、**日本国内からのアクセスだけに限定する**ことでまとめて消せる。
- 利用規約、プライバシーポリシー、18歳以上の自己申告、常時表示する注意書きを用意する。

## 2. 仕様の叩き台（推奨）

### ゲーム
| 項目 | 推奨 |
|---|---|
| 形式 | 3人、NLHE、ハイパーターボ。全倍率で**1位総取り**（ご要望どおり） |
| 抽選 | 3人がそろった時点でサーバーが倍率を抽選し、ホイールで演出（5〜8秒、スキップ可）してから開始 |
| 倍率表 | 03-economy.md §4（E[倍率]=3.0、レーキ0%、RTP100%）。最高賞金は全ステークで100,000チップに統一 |
| ステークス | Low 10 / Mid 100 / High 1,000 / Ultra 2,000 / Extreme 3,000（すべて最初から解放） |
| 初期配布 | 10,000チップ |
| 初期スタック・レベル時間 | 倍率で変える（PokerStarsの2025年以降の方式）: 2x=300・1分、3x=300・2分、4x=400・2分、5x=400・3分、10x/25x=500・3分、100x以上=500・5分 |
| ブラインド | 10/20, 15/30, 20/40, 30/60, 40/80, 50/100, 60/120, 75/150, 90/180, 100/200, 125/250, 150/300, 200/400, 250/500, 300/600, 400/800, 500/1000（以降は1.25倍刻み）。アンテなし |
| 持ち時間 | 1アクション15秒＋試合ごとのタイムバンク30秒（GGPokerは10〜30秒）。時間切れはチェック／フォールドで、3回続くとSit-out扱いでブラインドを払い続ける |
| フリーロール | 残高が10未満の人だけ参加できる。3人で1位総取り、固定賞金500、倍率抽選なし、1日3回（日本時間0時にリセット） |
| マッチング | ステークごとの待機キュー。3人そろえば即開始。15〜20秒たっても集まらなければBot（🤖表示、ランキング対象外）で補充 |
| ランキング | 所有チップ数で上位100人と自分の順位。**半年ごとにシーズン更新**（殿堂入りを記録したうえで、全員のチップを10,000に戻す。2026-10-04 さつき決定） |

### メニュー（Google認証後）
| ボタン | 内容 |
|---|---|
| **PLAY**（grid-holdemのVSPlayerに相当） | ステークス（10 / 100 / 1,000）を選んで待機キューに入る。各ステークの待機人数と、残高・解放状況を表示 |
| **FREEROLL** | 残り回数を表示（例: 2/3）。参加条件を満たさないときはグレーアウトし、理由をツールチップで表示 |
| **RANKING** | 所有チップ数ランキング |

- 「VS Player」は1対1を連想させるので、3人卓には「PLAY」が自然。
- 「SPIN」は商標（SPIN & GO）に近づくので避けた。

### アプリ名
**Multiplier**（2026-10-04 さつき決定）。日本の第9類・第28類・第41類に同名の登録はなく、侵害リスクは低い。表示は「Multiplier — 3人ポーカートーナメント」のようにサブタイトル付きにする（06）。

### サーバーのデータ
| データ | 保存場所 | 備考 |
|---|---|---|
| uid、プレイヤー名、所有チップ数 | profiles | 要件のとおり |
| フリーロールの日付と使用回数 | profiles | 1日の回数制限に必要な最小限の追加 |
| 進行中のゲーム | games | 一時データ。終局後に削除する |
| メールアドレス・氏名 | `neon_auth.user` | **Neon Authが自動で保存する。** プライバシーポリシーに記載が必要 |

## 3. 技術方針
- grid-holdemの構成をそのまま踏襲する: Vite＋素のJS、Cloudflare Pages、Neon Auth（Google）、Neon Functions、Neon Data APIのRPC、HTTPポーリング。
- **3人NLHEのエンジン（サイドポット等）は新しく書く。** `eval5`、`shuffle`、カード表現、UI基盤、認証、DB、スクリプト類は流用する。
- ブラインドの上昇とBotの手番は、常駐プロセスを置かず、ポーリングのたびにサーバーで判定する遅延評価方式で処理する。

## 4. 決定事項（2026-10-04 さつき）
1. アプリ名は **Multiplier**。
2. **Botで空席を埋める。** ただし弱すぎると拍子抜けするので、ある程度強くする。方針はプリフロップを Nash 表、ポストフロップをレンジ推定＋モンテカルロ計算＋ルールにする（05）。
3. **ランキングは半年ごとに更新する。**
4. 調査結果をリポジトリにコミットしてよい。

5. **アクセスは日本国内に限定する**（Pages Functions のミドルウェアで `request.cf.country` を判定する）。
6. **倍率表は推奨案を採用する**（RTP100%、3xが最頻、03-economy.md §4）。
7. **半年ごとのシーズン更新では、上位者を殿堂入りとして記録したうえで、全員のチップを初期値（10,000）に戻す**。殿堂入りは記録の表示のみで、特典は付けない。
